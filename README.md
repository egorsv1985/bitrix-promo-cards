# Тестовое задание: «Акции и спецпредложения»

Решение для стандартного компонента `bitrix:news.list`.
Условие: https://github.com/pragma-dev-company/bitrix-test-task

## Структура

Папка `local` располагается непосредственно в корне сайта.

- `local/templates/.default/components/bitrix/news.list/promo_cards/result_modifier.php` — подготовка данных.
- `local/templates/.default/components/bitrix/news.list/promo_cards/template.php` — разметка карточек.
- `local/templates/.default/components/bitrix/news.list/promo_cards/style.css` — адаптивные стили без зависимостей.
- `examples/include_component.php` — пример подключения на существующей странице.

`.default` — общий каталог шаблонов. Если в активном шаблоне сайта уже есть одноимённый шаблон компонента, он может иметь приоритет. В таком случае разместите `promo_cards` в `local/templates/<ID_шаблона_сайта>/components/bitrix/news.list/`.

## Уточнения и принятые решения

1. Работодатель подтвердил: `DATE_ACTIVE_TO` — стандартное поле окончания активности элемента. Создавать отдельное свойство не требуется. Дополнительно поддержан ключ результата `ACTIVE_TO`.
2. «Менее 3 дней» — строго меньше 72 часов, оставшихся до окончания. Ровно 72 часа не подходят. В момент окончания и после него `IS_HOT = false`.
3. В примере `CHECK_DATES = Y`: истёкшие и ещё не начавшиеся элементы отбираются стандартным компонентом по датам активности. Это принятая трактовка ответа работодателя о стандартном периоде активности.
4. Нет даты окончания — нет отметки «Заканчивается».

## Установка

1. Скопировать папку `local` в корень тестового сайта, сохранив структуру.
2. Подготовить инфоблок с активными элементами: название, картинка анонса, текст анонса, дата окончания активности.
3. Добавить одиночное числовое свойство `DISCOUNT_PERCENT` и одиночное строковое свойство `BADGE`.
4. В примере заменить `IBLOCK_TYPE` и `IBLOCK_ID` фактическими значениями и вставить вызов на страницу между подключениями `bitrix/header.php` и `bitrix/footer.php`. Сам файл примера не является самостоятельной страницей.
5. Очистить ранее созданный кеш, если компонент уже использовался на странице.

## Логика

- Данные обрабатываются в `result_modifier.php`, дополнительных запросов к БД нет.
- При скидке строго больше 20 выводится «Суперцена», иначе «Выгода».
- Вычисленный бейдж хранится в `$item['BADGE']`, скидка — в `$item['DISCOUNT_PERCENT']`. Значение свойства в БД не изменяется: исходный BADGE намеренно заменяется только для вывода по условию задания.
- Отсутствующая или нечисловая скидка не выводится; бейдж — «Выгода». Для корректных данных редактор должен задавать процент в диапазоне 0–100. Корректировка ошибочных числовых значений не входит в эту реализацию.
- Весь динамический текст экранируется. HTML-анонс преобразуется в обычный текст: форматирование HTML не сохраняется. Это исключает исполнение разметки и скриптов из описания.
- При отсутствии картинки выводится заглушка; пустой список имеет отдельное сообщение.
- Сохранены действия редактирования и удаления элементов в режиме правки Битрикс.
- Сетка: 3 колонки на широком экране, 2 до 991 px, 1 до 575 px.

## Даты и кеш

Дата разбирается штатным `MakeTimeStamp` с форматом сайта. Среда должна иметь согласованные настройки времени PHP и Битрикс; пользовательское смещение часового пояса необходимо отдельно проверить при интеграции.

В примере `CACHE_TYPE = N`: результат зависит от текущего времени. При включении кеша `result_modifier.php` не пересчитывается на каждом запросе, поэтому бейдж и состав списка могут устаревать до истечения кеша. Для этого небольшого тестового блока выбран простой вариант без кеша компонента. Полностраничный/композитный кеш также требует отдельной проверки; для первоначальной проверки используйте страницу без него. Открытая в браузере страница не обновляет бейджи автоматически — требуется перезагрузка.

## Сценарии проверки в Битрикс

Ожидаемые результаты ниже — план проверки, а не утверждение о выполненных тестах.

| Входные данные | Ожидаемый результат |
| --- | --- |
| Окончание через 71 час 59 минут | `IS_HOT = true`, красная отметка |
| Окончание ровно через 72 часа относительно момента расчёта | `IS_HOT = false` |
| Окончание через 4 дня | Нет красной отметки |
| Окончание сейчас или в прошлом | `IS_HOT = false`; при `CHECK_DATES = Y` истёкший элемент не попадает в список |
| Дата не заполнена | Нет красной отметки |
| Скидка 20 | «Выгода», скидка 20% |
| Скидка 20.5 или 25 | «Суперцена», соответствующий процент |
| Скидка 0 | «Выгода», скидка 0% |
| Скидка отсутствует или нечисловая | «Выгода», строка скидки отсутствует |
| Нет картинки | Заглушка |
| HTML в анонсе | Текст без HTML-разметки |
| Кавычки и угловые скобки в названии | Безопасный текст, не разметка |
| Нет элементов | Сообщение об отсутствии акций |
| Экран 375, 768 и 1280 px | 1, 2 и 3 колонки соответственно |

Пограничное значение 72 часа следует проверять с фиксированным временем: при ручном вводе до перезагрузки страницы пройдёт несколько секунд.

## Выполненные проверки и ограничения

23.09.2026: PHP 8.5.10 (WebAssembly, `@php-wasm/cli` 3.1.55): синтаксическая проверка всех четырёх PHP-файлов без ошибок; `tests/run.php` — **35 проверок пройдено**. На сервере с нативным PHP и установленным Битрикс запуск не выполнялся.

Предпросмотр проверен в Chromium на ширинах 375, 768 и 1280 px: соответственно 1, 2 и 3 колонки; горизонтального переполнения нет, демонстрационное изображение загружается. Внешний вид проверен на мобильной и настольной ширине. Отображение эмодзи зависит от шрифтов устройства.

Проверки выполняются отдельно от CMS. `tests/run.php` подключает реальные файлы решения, подменяя только необходимые функции и объект шаблона Битрикс. Даты в тестах — относительные фикстуры: штатный парсер дат Битрикс этим не проверяется.

Проверяются: границы 72 часа и окончания акции, отсутствующая/ошибочная дата, скидки 0/20/20.5/25 и некорректное значение, сохранение исходного свойства, экранирование названия, преобразование HTML-анонса, бейджи, заглушка и пустой список.

Запуск при наличии PHP из корня репозитория:

```bash
php tests/run.php
find local examples tests -name '*.php' -exec php -l {} \;
```

Тест также создаёт `preview/index.html` из настоящего `template.php`. Готовый предпросмотр включён в репозиторий: откройте его в браузере без PHP и Битрикс. Картинка `preview/sample.svg` — локальная демонстрационная иллюстрация, не обязательная часть шаблона.

На установленном 1С-Битрикс решение не запускалось. Не проверены интеграция с инфоблоком, реальный парсер и часовые пояса CMS, кнопки административного редактирования, фильтрация компонента и композитный кеш. Изолированные тесты не заменяют интеграционную проверку.

Файлы `tests` и `preview` не нужны на рабочем сайте. Ядро Битрикс, доступы и лицензионные данные не входят в решение.
