# Акции и спецпредложения

Шаблон `promo_cards` для компонента `bitrix:news.list`.
[Условие задания](https://github.com/pragma-dev-company/bitrix-test-task).

## Подключение

1. Скопировать папку `local` в корень сайта.
2. В инфоблоке заполнить название, картинку и текст анонса, дату окончания активности. Добавить одиночные свойства `DISCOUNT_PERCENT` (число) и `BADGE` (строка).
3. Вставить вызов из `examples/include_component.php` на страницу между подключениями `bitrix/header.php` и `bitrix/footer.php`. Указать свои `IBLOCK_TYPE` и `IBLOCK_ID`.

Для даты используется стандартное поле `DATE_ACTIVE_TO`, как уточнено в ответе к заданию. Отдельное свойство для неё не нужно.

Шаблон лежит в `local/templates/.default/components/bitrix/news.list/promo_cards/`. Если в активном шаблоне сайта уже есть `promo_cards`, нужно обновить его либо перенести файлы в каталог активного шаблона.

## Как работает

- `result_modifier.php` подготавливает данные без дополнительных запросов к БД.
- `IS_HOT` включается, если до окончания акции осталось больше нуля и строго меньше 72 часов. Пустая или истёкшая дата не даёт отметку.
- При скидке больше 20% выводится «Суперцена», иначе — «Выгода». Значение `BADGE` меняется только в результате компонента, не в инфоблоке.
- `template.php` выводит карточки. Динамический текст экранируется, HTML-анонс выводится как обычный текст. Для отсутствующей картинки предусмотрена заглушка.
- `style.css` задаёт сетку: 3 колонки на широком экране, 2 до 991 px и 1 до 575 px.

В примере включён `CHECK_DATES`: компонент отбирает элементы по периоду активности. Отсутствующая или нечисловая скидка не выводится; для заполненных значений предполагается диапазон 0–100.

Кеш компонента в примере отключён (`CACHE_TYPE = N`), чтобы отметка рассчитывалась по текущему времени при загрузке страницы. При включении кеша нужно учитывать задержку обновления отметок. Композитный кеш и настройки часового пояса следует проверить на целевом сайте.

## Просмотр и проверка

Для просмотра вёрстки без Битрикс скачайте репозиторий и откройте `preview/index.html` в браузере. Это статический пример, а не работающий инфоблок.

В `tests/run.php` — изолированные проверки расчётов и вывода. Они подключают файлы шаблона с заглушками функций Битрикс. Запуск из корня проекта:

```bash
php tests/run.php
```

При предыдущем запуске прошли 35 проверок в PHP 8.5 (WebAssembly); синтаксис PHP-файлов проверен. Вёрстка проверена в Chromium на ширинах 375, 768 и 1280 px. Тестовый скрипт также обновляет `preview/index.html`.

**На установленном 1С-Битрикс решение не запускалось.** Проверка с реальным инфоблоком, парсером дат, кешем и административными кнопками остаётся для интеграции. Папки `tests` и `preview` на сайт копировать не нужно.
